# 串口收发与消息界面验证（2026-10-25）

环境：Qt 6.11 / MinGW，互通虚拟串口 COM1、COM2（Eltima Virtual Serial Port 7），两端均为 115200、8N1、无流控制。

## 实际串口测试

使用生产 `SerialManager`，通过对端 `QSerialPort` 捕获原始字节，并用独立预期值核对。修复后 56 项生产断言全部通过。

- TXT 无行尾、LF、CR、CRLF；HEX 不自动附加行尾。
- HEX 空格、大小写、0x 前缀、全部 256 种字节值。
- UTF-8、GBK、GB2312、ASCII、ISO-8859-1 的发送与接收。
- BCC（逐字节 XOR）、Sum8、CRC16 Modbus 的预览和实发字节。
- 拆开的 UTF-8 三字节字符、四字节 emoji、GBK/GB2312 双字节字符。
- 32 KiB 长包、64 条连续排队发送的顺序与字节计数。
- 断开后发送错误、重新连接及重新发送。

发现并修复：

1. 接收时逐块独立解码会破坏跨块中文，改为保留解码状态。
2. 此虚拟驱动单次原生写入 8 KiB/32 KiB 时，对端只收到 4 KiB；同样数据分次写入可完整接收。生产发送改为每次至多 4 KiB，由 `bytesWritten` 推进，不插入或删除任何载荷字节；校验仍对整条消息计算。
3. TX 记录在整条消息完成写入后产生，检查写入返回值，并报告异步串口错误。
4. 停止位列表 1、1.5、2 对应 Qt 枚举 1、3、2，修正原映射。
5. 空指令不再尝试发送。

## 两个桌面窗口的实测记录

| 功能 | 输入与实际收到的字节 | 结果 |
| --- | --- | --- |
| COM1 → COM2 TXT | `QA-TEXT-01` → `51 41 2D 54 45 58 54 2D 30 31`（10 字节） | 通过 |
| COM2 → COM1 HEX | `00 01 7F 80 FE FF 0A`（7 字节，无额外换行） | 通过 |
| HEX 模式发送普通文本 | `AT+RST` → `41 54 2B 52 53 54`，模式仍为 HEX | 通过 |
| 中文编码与文本显示 | `串口测试` → `E4 B8 B2 E5 8F A3 E6 B5 8B E8 AF 95`，切换记录为 TXT 后显示原中文 | 通过 |
| BCC/XOR | `01 02 03` → `01 02 03 00`，预览 `00` | 通过 |
| Sum8 | `01 FF` → `01 FF 00`，预览 `00` | 通过 |
| CRC16 Modbus | ASCII `123456789` 的 HEX 字节 → 尾部 `37 4B`，预览一致 | 通过 |

以上桌面步骤同时核对了两窗口的 RX/TX 字节计数。

## 终端及菜单

终端改为只读可选文本，支持拖选、Ctrl+C、长消息展开，保留文本空白且按纯文本显示。指令菜单移除“勾选指令”，宽度按动作内容计算，并复用液态玻璃材质；主题按钮和三个点支持再次点击关闭。

63 项 QML 检查通过，覆盖选择复制、只读、长文本展开、菜单宽度与重复点击关闭、滚动时菜单关闭且锚点固定，以及已有发送控制、拖动排序等交互。5 项现有脚本回归检查通过。

另外，offscreen 加载生产 `SendController.qml`，以两个真实 `SerialManager` 连接 COM1/COM2 的 16 项工作流断言全部通过：自动转换回写、带校验发送、不同间隔的双向循环、停止后稳定、再次手动发送、断开自动停止与重连恢复。此项不依赖桌面输入。

再以两个 offscreen 窗口加载完整生产 `Main.qml`，使用真实串口及隔离的测试配置，14 项断言通过：手动发送和历史、指令发送、按库顺序循环、与手动重复发送以不同间隔并行、输入和模式及间隔独立、分别停止稳定、断开自动停止及重连恢复。仅系统磨砂辅助对象为空实现；发送、指令库、配置和记录对象均为生产实现。

真实串口及工作流断言合计 86 项通过。

完整 Main.qml 另有 13 项交互检查通过：主题弹窗的窗口坐标、范围、重复点击开关及外部点击关闭，以及生产 RX 信号生成消息后的纯文本显示、鼠标拖选、Ctrl+C 和粘贴到发送框。该测试不占用串口；offscreen 下通过 ListView.itemAtIndex 取得实际消息委托后再操作。

最新构建的两个原生桌面窗口连接 COM1/COM2 后，补充确认：

- 主题弹窗在窗口内正常显示，再次点击主题按钮关闭。
- 指令三个点再次点击关闭；右键菜单显示发送、格式切换、删除三个动作，宽度贴合文字。
- 右键后滚动指令，菜单立即关闭，没有随卡片飞到标题栏。
- COM2 发送 `<b>QA-COPY-01</b>`，COM1 收到完整 17 字节，TXT 记录按纯文本显示标签。
- 接收文本可拖选并显示强调色高亮，双击选词、Ctrl+A、Ctrl+C 后粘贴到发送框，得到完整原文；点击发送框后终端选区清除。

## 复现真实回环

在已配置好互通 COM1、COM2 的机器上执行（端口应处于空闲状态）：

```powershell
cmake -S tests/serial_loopback -B _verify_build/serial-loopback -G Ninja -DCMAKE_PREFIX_PATH=D:/Qt/6.11.0/mingw_64
cmake --build _verify_build/serial-loopback
./_verify_build/serial-loopback/serial_loopback_test.exe
./_verify_build/serial-loopback/serial_qml_workflow_test.exe
```

运行时需将 Qt、MinGW 工具目录加入 PATH。详细结果输出到 `_verify_build/serial-loopback-results.json`；失败时程序返回非零退出码。

完整 Main.qml 工作流可单独构建：

```powershell
cmake -S tests/serial_main_workflow -B _verify_build/serial-main-workflow -G Ninja -DCMAKE_PREFIX_PATH=D:/Qt/6.11.0/mingw_64
cmake --build _verify_build/serial-main-workflow
./_verify_build/serial-main-workflow/serial_main_workflow_test.exe
```

不占用串口的主题弹窗和终端选择检查：

```powershell
cmake -S tests/theme_popup -B _verify_build/theme-popup -G Ninja -DCMAKE_PREFIX_PATH=D:/Qt/6.11.0/mingw_64
cmake --build _verify_build/theme-popup
./_verify_build/theme-popup/theme_popup_interaction_test.exe
```
