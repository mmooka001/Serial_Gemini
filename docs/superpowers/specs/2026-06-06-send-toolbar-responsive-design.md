# 发送工具栏响应式收缩设计

## 目标

修复右侧功能面板向左移动或加宽时，发送卡片顶部工具栏与面板发生重叠、穿模的问题。

发送区域应优先随可用宽度向左收缩。空间不足时，辅助组件按固定顺序逐个淡出并释放布局宽度；发送按钮始终保留，并持续随输入区域右边界向左移动。

## 适用范围

- 仅调整 `Main.qml` 中 `sendCard` 顶部工具栏及发送输入行的响应式布局。
- 不改变右侧功能面板的拖拽范围。
- 不改变串口发送、校验、自动发送、收发显示模式等业务逻辑。
- 不调整组件正常宽度下的视觉样式。

## 收缩行为

顶部工具栏中的可选组件按以下顺序隐藏：

1. 校验下拉框
2. 自动发送按钮
3. TIME 按钮
4. 发送模式组件
5. 接收模式组件

窗口或中间区域重新变宽时，组件按相反顺序恢复。

每个组件组使用独立的 `centerWidth` 阈值。达到阈值时：

- `opacity` 从 `1` 动画到 `0`。
- 布局宽度同步动画收缩到 `0`，避免透明组件继续占位。
- 动画结束后关闭交互和实际显示，防止不可见控件接收鼠标或键盘事件。
- 恢复时先重新参与布局，再执行宽度展开和淡入动画。

阈值之间保留足够间隔，确保拖动右侧面板时组件逐个消失，而不是同时切换。

## 布局约束

- 发送按钮保持固定 `55px` 宽度，不参与隐藏。
- 校验结果预览继续根据是否启用校验显示，但不得挤压发送按钮或越过发送卡片边界。
- 输入框保持弹性宽度，吸收剩余空间变化。
- 工具栏和发送输入行继续由现有 `RowLayout` 管理，避免引入绝对定位。
- `sendCard` 保持裁剪边界，作为异常情况下的最终视觉保护。

## 动画

- 淡入淡出使用短时 `NumberAnimation`，建议约 `120-180ms`。
- 宽度收缩与透明度动画同步。
- 使用缓出曲线，保持右侧面板拖动时的响应感。
- 发送按钮不做淡出或缩放动画，只跟随布局连续左移。

## 验证

1. 打开右侧功能面板并拖动其左边缘持续加宽。
2. 确认顶部组件按指定顺序逐个淡出。
3. 确认发送按钮全程可见，并持续向左移动。
4. 确认任何宽度下都没有组件越过发送卡片或覆盖右侧面板。
5. 反向缩小右侧面板，确认组件按相反顺序逐个淡入。
6. 验证隐藏前后收发模式、时间戳、自动发送和校验选择状态保持不变。
7. 在窗口最小宽度及功能面板最大宽度下检查输入框和发送按钮仍可用。
